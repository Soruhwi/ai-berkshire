# 심층 기업 시리즈: 8편의 장문으로 한 기업을 해부하다

$ARGUMENTS 를 위해 공중계정(공식계정)/영상계정 등 공개 채널에 발행할 8편짜리 심층 장문 시리즈를 집필한다. **핵심 IP는 "잘 쓰는 것"이 아니라 "잘 고치는 것"이다 — 99%의 경제 기사가 본 skill의 팩트체크 기준을 위반한다**.

참고 샘플: `reports/腾讯/《看懂腾讯》/`

---

## 1. 트리거 상황

사용자가 한 기업에 대해 "교과서 수준"의 심층 연구를 하고, 이를 **시리즈 장문** 형태로 공개 발행하고자 하는 경우. 단일 리포트와의 차이:
- 8편 약 12만 자, 인식 리셋부터 의사결정 프레임워크까지 완결 고리를 이룸
- 각 편은 독립된 글(단편 공유에 적합)이지만, 하나의 밸류에이션/경영진/가격 판단 체계를 관통함
- "한 기업을 이해하는 데 90분을 기꺼이 쓰는" 독자를 위한 글이지, 증권사 고객을 위한 글이 아님

**본 skill을 쓰기에 부적합한 상황**: 단편 리포트, 분기 실적 코멘트, 산업 연구 — 그런 것들은 `/investment-research`, `/earnings-review`, `/industry-research`를 사용한다.

## 2. 시리즈 편성 템플릿 (8편)

| # | 편명 템플릿 | 핵심 질문 | 글자 수 |
|---|---------|---------|------|
| 01 | 당신은 X를 이해했다고 생각하지만, 사실은 아니다 | 인식 리셋: 흔한 착각 3가지 깨기 | 4,000-5,000 |
| 02 | X의 해자 — `<사업 본질 한 문장>` | 해자가 깊은가, 향후 5/10년에도 남아있을까 | 6,000-8,000 |
| 03 | X의 최대 이익 엔진 — `<가장 돈 버는 사업>` | 주력 사업은 무엇이며, 왜 지속 가능한가 | 6,000-8,000 |
| 04 | X의 장부에 숨은 또 하나의 회사 — `<숨은 자산>` | 투자 포트폴리오 / 자회사 / 숨은 가치 | 8,000-10,000 |
| 05 | AI(또는 당대 내러티브) 시대, X는 승자인가 패자인가 | 시대 변수: 사업별 AI 영향 해부 | 8,000-10,000 |
| 06 | 버핏 방식으로 X의 실적을 해부하다 | 재무 심층: 매출총이익률/FCF/ROE/SBC | 8,000-10,000 |
| 07 | `<경영진 명언>` — X의 경영진은 맡길 만한가 | 자본배분 규율 + 정직성 검증 + 후계자 | 8,000-10,000 |
| 08 | 얼마면 살 만한가, 어떤 신호면 반드시 팔아야 하나 (시리즈 종장) | DCF 3시나리오 + 레드라인 체크리스트 + 포지션 프레임워크 | 10,000-12,000 |

`00-시리즈 설명.md` 한 편을 목차 색인으로 추가하되, 발행하지 않는다.

## 3. 집필 스타일 규범

### 어조

- **직접적, 날카롭게, 군더더기 없이** — 첫 문장부터 숫자나 반(反)직관적 결론을 던진다
- **가치투자 프레임워크** — 버핏/멍거/돤융핑/리루 관점을 교차 배치(단, 명언을 쌓아두지 않는다)
- **입장을 미리 정하지 않는다** — 먼저 데이터를 깔고, 다음에 논리를 펴고, 마지막에 결론을 낸다
- **양면을 모두 제시한다** — 모든 핵심 판단에 "하지만 다른 한편으로는…"이라는 반대편을 덧붙인다
- **공중계정 체감** — 앞 18-20자가 단독으로 성립해야 한다(휴대폰 미리보기)

### 금지어

| 금지 | 이유 | 대체 |
|------|------|------|
| 분명히 / 필연적으로 / 반드시 | 주관적 절대화 | 데이터가 보여주듯 / 증거가 시사하듯 |
| 나는 ~라고 생각한다 / ~인 것 같다 | 주관적 어조 | 삭제하거나 "본 프레임워크에 따르면"으로 변경 |
| 교과서 수준 / 신의 한 수 | 트래픽 노린 찬사 | 구체적 사실을 묘사 |
| 심각하게 불일치 / 심각하게 저평가 | 강한 주관어 | 구체적 할인 퍼센트를 제시 |
| 완벽 / 흠잡을 데 없음 | 일방적 판단 | 반대편 관찰을 덧붙임 |

### 제목 스타일

- **반전 숫자**나 **반(反)컨센서스 결론**을 후크로 사용("15년간 7번 도전 전부 실패", "연봉 4292만, 이익의 0.0017%")
- 부제는 중립적이고 내용을 요약("— `<본질 판단>`")
- **트래픽 노린 비유 회피**: "작은 버핏", "중국판 X", "YYDS" 일률 회피
- 전문 독자에게 익숙한 용어를 사용("버크셔"가 "버핏"보다, 회사명이 인명보다 우선)

## 4. 엄격한 팩트체크 체크리스트 (핵심 IP)

### 쓰기 전부터 경계해야 할 "유사(類似) 정밀" 함정

1. **확률 가중 기대값**: `30% × A + 50% × B + 20% × C = 기대 +X%` 같은 계산은 거의 전부 쓰레기다 — 확률 배분이 순전히 주관적이라 독자에게 잘못된 정밀감을 준다. **시나리오 + 트리거 조건 + 방향만 나열하고, 가중 기대값은 계산하지 않는다**.
2. **제3자 추정 MAU/점유율**: QuestMobile/七麦/CBNData 등은 기준 차이가 매우 크다(같은 시점에 2-3배 차이). **가장 신뢰할 만한 두 비교만 앵커로 쓰고, 나머지는 정성적으로 서술한다**.
3. **과거 성장률의 선형 외삽**: `2025년 +33% × 5년 복리 → 2030년 X`는 금융 문맹식 예측이다. **시나리오 가정 + 상/하 구간 + 약속이 아님**.
4. **미공개 지분율**: 바이트댄스, Halti류 비상장 기업 지분은 **공개 공시된 적이 없다**. **구간을 제시하고 "알 수 없음"으로 표기한다**.
5. **강한 귀인(歸因)**: 경쟁사 실패 = X 때문. 여러 원인을 모두 나열하고, **본 글은 단일 귀인을 하지 않는다**.

### 수정 시 반드시 돌려야 할 7개 점검

```
□ 1. 편 간 숫자 일관성: 총 시가총액, Non-IFRS 순이익, 핵심 지분 % 전 시리즈 정렬
□ 2. 기준 표기: Non-IFRS / GAAP / Non-IFRS-SBC / FCF 각각 어느 것을 쓰는지 전문에 명확
□ 3. 중복 가산 스캔: 이미 연결한 자회사는 "투자 포트폴리오"에 넣지 않음, SOTP 이중 계산 금지
□ 4. 횡적 비교 공정성: "주력사업 PE(현금+포트폴리오 차감)" vs "경쟁사 PE(미차감)"는 불가
□ 5. 확률 가중 전부 삭제: 위 항목 참조
□ 6. 절대화 표현 전부 약화: grep "분명히|필연|심각|교과서|완벽"
□ 7. 제3자 데이터 출처 표기: 비(非)실적 데이터 뒤에 "(출처: X)" 부기
```

### 모델 선호

쓰기 전 **이미 알려진 하드 에러 리스크를 먼저 나열**한다:
- 과거 수익 배수: 반드시 누적 투입 기준 사용(예: Riot 33배이지 58배 아님)
- 지분율: 반드시 최신 푸투(富途)/실적 기준 확인(예: 텐센트가 메이투안 1.5% 보유이지 6.4% 아님)
- "배당 분배" 회계 처리: 처분 간주 이익은 IFRIC 17에 따라 선언일에 인식(예: 징둥은 2021, 메이투안은 2022이나 금액 작음)
- 총 주식 수는 반등한다: SBC가 연초에 집중 부여되면 주식 수가 단기 상승

## 5. 실행 프로세스

### 단계 1: 조사 (01-02편 집필 전 완료)

1. 회사의 최근 5년 연차보고서, 최신 분기보고서 읽기
2. 최소 3개의 독립 셀사이드 리포트 읽기(컨센서스 + 반컨센서스 찾기)
3. `/investment-team` 또는 `/investment-research`로 먼저 내부 연구 초안 생성
4. 8편의 핵심 논점을 사용자와 확인(다 쓴 뒤에야 방향이 틀린 걸 발견하는 일 방지)

### 단계 2: 집필 (01→08 순서로, 건너뛰지 않음)

- 각 편을 다 쓰면 먼저 `reports/{회사명}/《看懂{회사명}》/0X-XX.md`에 저장
- 즉시 GitHub에 푸시하지 않음 — 사용자 검토 대기
- 사용자가 수정 의견을 주면 수정
- 수정 완료 후에야 git push

### 단계 3: 편 간 일관성 스캔 (8편 전부 작성 후)

Explore agent를 보내 8편을 병렬 스캔하여 다음을 점검:
1. 동일 숫자(시가총액, 순이익, 지분율)가 편 간 일치하는지
2. 동일 용어(FBS, SBC, Non-IFRS)가 처음 등장할 때 설명되었는지
3. 인용 관계: 02편이 "06편 참조"라 했을 때 실제로 대응하는지
4. 요점 정리 vs 본문의 숫자가 일치하는지

### 단계 4: 발행 전 최종 점검

```bash
# 푸시 전 반드시 로컬에서 grep 1회(ai-berkshire 프라이버시 규칙에 따라)
grep -r "linxuan\|/Users/\|<사용자 회사 별칭>" reports/ | head
```

이상 없음을 확인한 후에야 `git pull --rebase && git commit && git push`.

## 6. 수정 의견 처리 프로세스

사용자가 수정 의견을 줄 때, 다음 순서로 처리한다:

### 1. 먼저 사실을 검증(바로 고치지 말 것)

사용자가 "X 데이터가 틀렸다"고 하면, 먼저 Bash/Read로 원천 데이터를 찾아 교차검증한다:
- ai-berkshire 프로젝트 내 동일 회사의 earnings/실적 리포트 확인
- 푸투/공식 공시 확인
- "사용자가 말한 데이터 vs 내가 찾은 데이터 vs 내가 이전에 쓴 데이터" 3자 대조 제시

### 2. 수정 레벨 판단

| 레벨 | 유형 | 처리 |
|------|------|------|
| 🔥 하드 에러 | 숫자 오류, 귀인 오류, 기준 오류 | 반드시 수정, 망설일 필요 없음 |
| ⚠️ 주관화 | 강한 주관어, 절대화, 트래픽 노린 비유 | 약화 또는 삭제 |
| 🔬 입자도(粒度) | 출처 표기, 기준 세분화 | 우선순위 낮음, 가독성과 균형 |
| ❓ 불신뢰 | 제3자 추정 차이 큼 | **고치기보다 삭제가 더 안전**(사용자 명시 지시) |

### 3. 수정 후 연동 점검

한 곳을 고치면 먼저 "어느 곳들이 이 숫자/개념을 또 인용하는지" 생각한다. 예:
- 총 시가총액 변경 → 전 시리즈 연동하여 PE / 주력사업 PE / 할인 / FCF Yield 수정
- 지분 % 변경 → TOP 10 순위 + 과거 지분 표 + 매도 리스트 수정
- 용어 기준 변경 → 최초 정의 + 후속 인용 + 요점 정리 수정

### 4. 푸시 후 즉시 보고

```
푸시 성공(commit hash).
[N]건 수정 요약 [표 포함]:
- 무엇을 고쳤는지
- 연동하여 무엇을 고쳤는지
- 아직 고치지 않은 것은 무엇인지

다음 단계 지시 대기.
```

## 7. 본 skill이 하지 않는 것

- **독자를 대신해 투자 결정을 내리지 않는다** — 모든 편 말미에 "투자 조언을 구성하지 않음"
- **주가를 예측하지 않는다** — "시나리오 + 트리거 조건"만 제시
- **"기대 연환산 수익"의 가중값을 계산하지 않는다** — 주관적 확률 배분은 독자를 오도한다
- **"X 거물도 보유 중"이라고 쓰지 않는다** — 타인의 보유를 자기 판단의 보증으로 삼는 것은 반(反)가치투자다
- **8편을 억지로 다 쓰지 않는다** — 어떤 편에 독립된 내용이 충분치 않으면(예: 어느 회사의 경영진이 그리 특별하지 않으면) 다른 편에 합치거나 편수를 줄인다

## 8. 컴플라이언스와 프라이버시

- 모든 공개 리포트는 **공개 정보만 사용**(실적, 공식 공시, 증권사 리포트, 유명 제3자 기관)
- 어떤 **사용자 개인정보**도 사용하지 않음(회사 별칭, 내부 IM, 미공개 보유 정보)
- 푸시 전 반드시 grep으로 `linxuan` / `/Users/` / 사용자 회사 별칭 등 프라이버시 필드 스캔(`~/.claude/projects/-Users-linxuan/memory/feedback_privacy_upload.md` 참조)
- 공개 서명은 사용자의 다층 신원 전략에 따르며, 혼용하지 않음

## 한 문장 요약

**《X 이해하기 시리즈》를 쓰는 핵심 능력 ≠ 잘 쓰는 것, 오히려 엄격하게 고치는 것** —
89%의 경제 장문이 유사 정밀 숫자, 주관적 가중 기대값, 절대화 표현 때문에 죽는다. 본 skill의 존재 이유는 이 함정들을 전부 표시해 두어, 쓰기 전에 피하고 쓴 후에 깨끗이 쓸어내는 것이다.
